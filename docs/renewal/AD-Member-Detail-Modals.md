## 계정 통합 상세 모달
- "계정 통합" 행의 "계정 통합 상세"로 연다. UI는 디자인 그대로(통합 결과 표 + 통합 상세 카드 목록 + 닫기).
- **데이터 없음**: 현재 회원 상세 응답에 통합 정보가 없어 값은 `-`, 목록은 "통합 이력이 없습니다."로 보인다.
- 필요한 API 계약은 `model/merge.ts`의 `AccountMergeDetail`이다.
  - `result`: 이름, 휴대폰, 생년월일, 가입일, 보유 쿠폰, 구매 이력, 회원 등급, 소셜 연동, 이메일, 보유 포인트, 계정 통합일, 유의사항 동의일
  - `sources[]`: 합쳐진 원본 계정별 이메일, 휴대폰, 이름, 생년월일, 포인트, 쿠폰, 구매 이력, 등급, 소셜 연동, 가입일

## 회원 등급 변동 탭
- 데이터: `useMemberView`의 `level_history`(`history_date`, `mem_level`, `order_price`).
- 열: 산정일 / 산정 기간 / 최근 구매 총액 / 이전 등급 / 변경 등급(+승급·강등·유지 태그) / 계정.
- 산정 기간은 기획대로 산정일 직전 6개월(예: 2026-07-01 → 2026-01-01 ~ 2026-06-30)로 계산한다. 정렬은 산정일 내림차순.
- 이전 등급은 바로 앞(더 오래된) 이력의 등급이다. 가장 오래된 이력은 이전 등급을 알 수 없어 `-`이고 태그도 없다.
- 확인 필요: 서버가 이전 등급/변동 상태를 직접 내려주는지, "유지" 태그 색(디자인에서 회색 계열로 추정해 `bg sub`로 구현), 이력이 월 단위(`YYYY-MM`)로만 오는 점.

## 혜택 내역 탭 (미구현 사유)
- 기획서(AD-Member-Detail-03)에서 혜택 내역 표는 **"기획대기"** 표시이고 열이 `혜택 구분/혜택/사유/쿠폰 상태`다.
- 반면 디자인(`30164:10942`)의 표는 주문 내역과 같은 열(`주문 번호/결제 번호/주문 상품/계정/주문 금액/주문 상태`)에 칩만 `전체/포인트/쿠폰`으로 바뀌어 있어, 복사된 임시 화면으로 보인다.
- 열 정의와 데이터(포인트 지급/차감, 쿠폰)가 확정되면 구현한다.
