# 기능 동일성(Function Parity) 검증 체크리스트

> 화면 구현보다 **기존 기능과 동일하게 동작하는지 확인**이 더 중요하다.
> 각 단위는 이 체크리스트를 통과해야 다음 단위로 넘어간다.

## 단위 검증 (단위마다)

### 프로젝트 분석
- [ ] 프로젝트 구조를 이해했는가?
- [ ] include 관계를 분석했는가?
- [ ] Database 구조를 이해했는가?

### 기능 분석
- [ ] Request를 이해했는가?
- [ ] Response를 이해했는가?
- [ ] Session을 이해했는가?

### 화면 분석
- [ ] Component 분리가 가능한가?
- [ ] Layout을 분리했는가?
- [ ] 공통 UI를 추출했는가?

### 인증
- [ ] 로그인 / 로그아웃 / 권한 확인 / Redirect 동작 동일

### Database
- [ ] CRUD 확인 / Transaction 확인 / SQL Injection 방지 확인

### API 계약 (B 백엔드 분리형 — directg-front)
- [ ] legacy SQL/로직에서 요청·응답 스키마를 도출했는가?
- [ ] 검증 규칙 / 에러 응답 / 상태코드를 계약에 명시했는가?
- [ ] 계약을 `docs/migration/`에 문서로 기록했는가? (백엔드 전달용)
- [ ] 백엔드 미완이면 계약대로 MSW mock을 만들었는가?
- [ ] 프론트는 `packages/api-client`로만 호출하고, SQL·비즈니스 로직을 프론트에 두지 않았는가?

## 동일성 테스트 (가장 중요)

기존 PHP 화면과 나란히 비교한다:

- [ ] 기존 화면과 **동일한 결과**인가?
- [ ] **동일한 Validation**인가?
- [ ] **동일한 Error Message**인가?
- [ ] **동일한 Redirect**인가?
- [ ] **동일한 권한 체크**가 되는가?

## 검증 게이트 (단위 완료 시 정지)

> 프로젝트 지침(`AGENTS.md`)과 동일 — 승인 전까지 다음 단위 착수 금지.

- [ ] parity 보고서를 개발자에게 제시했는가?
- [ ] 개발자가 legacy와 대조·승인했는가?
- [ ] `docs/MIGRATION-MAP.md`의 해당 단위 상태를 갱신했는가? (✅는 **개발자 승인 후에만** 기록)

## 완료 기준 (전체 이관)

- [ ] 모든 화면이 동일하게 동작한다
- [ ] 모든 CRUD 기능이 정상 동작한다
- [ ] 인증 및 권한이 동일하게 동작한다
- [ ] Database 변경 없이 서비스가 운영된다
- [ ] 기존 사용자 경험이 유지된다
- [ ] 기능 회귀(Regression)가 발생하지 않는다
